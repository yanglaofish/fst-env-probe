## 已修复的问题

| 问题 | 影响与修复 |
| --- | --- |
| Windows 共享服务直接启动 `.cmd/.bat` 返回 `spawn EINVAL` | `npm.cmd` 等工具只能找到路径而无法读取版本。回退实现改用正确的 cmd 调用方式，验证了中文、空参数、引号、百分号及特殊文件名，并拒绝批处理换行参数。 |
| Python 专题与通用工具解析结果不一致 | 基线 Windows 测试失败：Python 专题能找到 Conda 注册解释器，`detect.paths.python` 却为空。统一 Conda 活动环境、注册表、Windows `py -0p` 的发现范围，使 detect/check/resolve/Python 专题共享候选来源；verify 复用 resolve。 |
| resolve 忽略 `installPatterns` | PATH 外的已知安装能被 check/detect 找到，却不能用于工作流解析和要求校验。改用统一发现逻辑，同时保留显式 `names` 仅搜索指定命令的含义。 |
| 缓存忽略输入优先级和环境变化 | `extraPaths` 排序改变搜索优先级，`allowRemoteMounts`、JAVA_HOME、CONDA_PREFIX 等变化可能命中旧结果。缓存保留目录顺序、纳入远程扫描选项及完整环境摘要，摘要不包含环境变量明文。 |
| 额外目录展开使用宿主环境 | 调用方传入的 `env` 中 HOME、USERPROFILE 和 `%VAR%` 未参与展开。所有入口现在使用本轮环境。 |
| 刷新、取消和扩展名处理不完整 | check 的 refresh 不清目录缓存；缓存命中或纯环境采集忽略已取消信号；Windows `node.exe` 被再次追加扩展名。均已修复并增加回归。 |
| 完整路径和无通配安装路径绕过扫描防护 | 对 stat/access/realpath/注册表读取统一应用远程挂载跳过、等待上限及取消处理，记录跳过和超时信息。 |
| 回退进程超时后可能遗留子进程 | 回退实现加入 Windows 进程树与 POSIX 进程组回收，保留非零退出码、编码、取消、输出上限语义；已验证继承输出管道的子进程被回收。 |
| 报告将采集失败标为成功 | report 不再固定返回 `ok: true`，保留真实采集状态、errors 和 scan；报告文件仍可用于诊断。条件“报告采集成功”与字段含义一致。 |
| 新版宿主声明和说明不足 | 补充普通用户权限、独立命令标题及 `runtime.updatePolicy: automatic`，缓存服务可在空闲时定向重启；配置修改无需进入全局维护模式。删除重复命令定义，修正安装和运行说明。 |

`report.ok` 的修正需要使用方留意：若只判断“报告文件已写出”，请检查 `files` 中对应路径；若判断采集成功，则继续使用 `ok` 或预设条件。未找到可用解释器时，Python 专题不再把不可用候选作为 primary，也不再返回成功。

## 尚未验证或仍受平台约束的部分

- macOS、arm64 及实机 Ascend/NVIDIA/容器/Kubernetes 的各类驱动组合不能由本机覆盖；现有解析回归和 CI 矩阵用于后续验证。
- Linux 容器验证了真实 Linux 分支与真实宿主，但不能代表实体 Linux 主机全部硬件、挂载及网络配置。
- 异步文件扫描超时停止等待，无法强行取消内核 I/O。远程挂载识别失败、符号链接跨远程位置或主动允许远程扫描时，底层调用仍可能继续等待。已在 README 说明实际边界。
- 最新宿主 CI 安装官方 npm `latest` 后运行集成测试，可以发现未来升级回归；它不能预先保证未来所有宿主版本兼容。
